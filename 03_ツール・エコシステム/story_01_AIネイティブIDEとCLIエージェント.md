## 第1部：ストーリーで読む「最強のAI開発環境を組み立てる」

実装が本格化する中、ミサキは「どのツールをどう使い分ければいいのか分からない」と悩んでいた。サトウが画面を共有しながら、現代のAI開発ツール群の全体像と実践テクニックを案内する。

### シーン1：AIネイティブIDEとCLIエージェントの使い分け

**ミサキ**：「Cursor、Windsurf、Claude Code、Gemini CLI、GitHub Copilot……ツールが多すぎて、どれを使えばいいのか迷ってしまいます」

**サトウ**：「大きく3つのカテゴリで整理するとスッキリするよ。
1つ目は、エディタ自体がAI協働前提で作られた**AIネイティブIDE**だ。**Cursor**や**Windsurf**、仕様駆動に強い**Kiro**、あるいは既存のVS Codeに拡張として入れる**GitHub Copilot**、**Cline**、**Roo Code**が代表格だね。画面上で**インライン補完（Ghost Text）** や**Diffプレビュー・ハンク承認**を見ながら直感的に作業できるのが強みだよ」

**ミサキ**：「2つ目はターミナル系のツールですか？」

**サトウ**：「そう、**Claude Code**、**Gemini CLI**、**Codex CLI**、**Aider**みたいなCLIエージェントだ。リポジトリ全体を横断してコマンド実行・テスト・Git操作を自律的に回せるし、UIなしでCIパイプラインから動かす**ヘッドレスエージェント実行**や**エージェントCLIのCI統合**とも相性が抜群なんだ」

**ミサキ**：「じゃあ3つ目は？」

**サトウ**：「UI試作に特化した**v0**、ブラウザ内でフルスタック環境を即座に動かす**Bolt.new**や**Lovable**、クラウド上で完結する**Replit Agent**や**Firebase Studio**のようなビルダー／クラウド系だね。さらにIssueからPRまで自律完遂を狙う**Devin**やオープンソースの**OpenHands**のような自律エージェント環境もあるよ」

---

### シーン2：3つの動作モードと安全な操作テクニック

**ミサキ**：「AIネイティブIDEを開いてみたんですけど、いきなりエージェントにコードを書かせるのはちょっと緊張します……」

**サトウ**：「だからこそ、動作モードの切り替えが大切なんだ。
最初はファイル変更を禁止してコード解説や相談だけ行う**アスクモード（Ask Mode）** で調査する。次に、実装前に要件整理と手順書づくりに専念する**プランモード（Plan Mode）** で方針を合意する。そして最後に、ファイル検索・編集・テスト実行を自律ループで回す**エージェントモード（Agentic Mode）** へ切り替えるんだ」

**ミサキ**：「なるほど、段階を踏めば安心ですね！プロンプトに `@file` って打つと候補が出てきました」

**サトウ**：「それが**コンテキストメンション（@シンボル）** だよ。裏ではリポジトリ全体を検索可能にする**コードベースインデックス**や、型情報・定義ジャンプを渡す**LSP連携（Language Server Protocol）**、構文木を高速解析する**ASTベースコード解析（Tree-sitter）** が動いている。もしエージェントが変な方向へ進んでしまっても、直前の状態へ一瞬で戻せる**チェックポイント・ロールバック**があるから恐れずに試せるよ」

---

### シーン3：自律ループ・並列開発・PRレビューの自動化

**ミサキ**：「エージェントが内蔵ターミナルで勝手にテストを実行して、エラーが出たら自分で直して再実行しています！すごい！」

**サトウ**：「それが**ターミナル統合実行**による**自動エラー修正ループ**だね。フロントエンドなら**ブラウザプレビュー統合**で画面表示やコンソールログまでAI自身が確認できるんだ。さらに慣れてきたら、1つのGitリポジトリから複数の作業ツリーを切り出す**Git Worktree並列開発**や、ローカル作業を邪魔せず非同期で動かす**バックグラウンドエージェント**を使って、複数タスクを同時進行できるよ」

**ミサキ**：「並列でPRが増えてくるとレビューが大変になりそうですが、レビュー支援ツールもありますか？」

**サトウ**：「もちろん。PRに自動で詳細コメントを付けてくれる**CodeRabbit**や、リポジトリ全体の依存関係を踏まえて指摘する**Greptile**、テスト生成と品質検証に強い**Qodo**などを組み合わせると、人間のレビュー負担を劇的に減らせるんだ。こうしたツール同士の性能比較には、実在するGitHub Issueの解決率を測る**SWE-bench**などのベンチマークがよく参考にされるよ」

### シーン4：コスト最適化と企業導入のセキュリティ要件

**ミサキ**：「長時間エージェントとやり取りしていると、トークン消費や料金が気になってきました。あと、会社のコードを外部モデルに送っても大丈夫なんでしょうか？」

**サトウ**：「いい視点だね。まずコストとコンテキスト対策としては、長くなった会話履歴を自動で要約圧縮する**会話コンパクション（Compaction）**、共通プロンプトを再利用して遅延と課金を減らす**プロンプトキャッシュ活用**、そしてタスク難易度に応じて軽量モデルと高性能モデルを使い分ける**スマートモデルルーティング**や**マルチモデル切替**が効くよ。セッションごとの消費量を把握する**コスト・トークン可視化**も常に見ておこう」

**ミサキ**：「セキュリティ面はどう担保しているんですか？」

**サトウ**：「企業導入では、プロバイダ側でコードの保存や学習利用を一切行わない**ゼロデータ保持（ZDR）** の契約が基本だ。さらに機密性が高いプロジェクトでは、自分のAPIキーを使う**BYOK（Bring Your Own Key）** や、外部クラウドへ送信せず社内・端末内で完結させる**ローカルファーストAI開発**を選ぶこともある。生成コードがOSSライセンスに抵触しないか確認する**コード帰属・ライセンス検査**も合わせて押さえておけば、安心して**AIペアプログラミング**を回せるよ」

   「**会話コンパクション**・**プロンプトキャッシュ活用**・**スマートモデルルーティング** でコストを抑えつつ、**ゼロデータ保持（ZDR）** と **コード帰属・ライセンス検査** で安全な開発環境を維持する。」

## 第4部：現場で活かす深掘り解説

### 1. 実務の判断基準：IDE・CLI・ビルダーの使い分け早見表

| ツール種別 | 代表例 | 得意な場面 | 苦手な場面・注意点 |
|---|---|---|---|
| **AIネイティブIDE** | Cursor / Windsurf / Kiro / Cline | 既存コードを読みながらの対話実装、細かいDiff確認、UIとコードの往復 | サーバー上でのバッチ処理やCIからの完全自動実行 |
| **CLIエージェント** | Claude Code / Gemini CLI / Codex CLI / Aider | 複数パッケージ横断の変更、テスト→修正の自律ループ、CI統合（ヘッドレス実行） | 視覚的なUI崩れの確認、カーソル単位の細かなインライン補完 |
| **クラウドビルダー** | v0 / Bolt.new / Lovable / Replit Agent | 0→1のプロトタイピング、PMやデザイナー主導の試作品づくり | 複雑な社内認証・独自インフラ・既存大規模モノレポへの統合 |

> **現場の鉄則**：日常開発では「**IDE（視認性・細部編集）＋ CLIエージェント（自律ループ・横断作業）**」の二刀流が最も生産性が高く、企画初期だけビルダーでプロトタイプを作るハイブリッド運用が定着しています。

---

### 2. よくある失敗パターン（アンチパターン）と回避策

#### 失敗①：いきなり「エージェントモード」で大規模変更を投げる
- **起きること**: 要件の解釈ズレに気づかないまま十数ファイルが書き換わり、レビュー不能な巨大Diff（差分）が生まれて手戻りが発生する。
- **回避策**: 必ず **アスクモード（調査）→ プランモード（変更計画の合意）→ エージェントモード（実行）** の3段階を踏む。着手前にチェックポイント作成や `git status` のクリーン確認を習慣化する。

#### 失敗②：コンテキストを詰め込みすぎて精度とコストが悪化する
- **起きること**: 無関係なファイルまで `@folder` で大量参照させ、トークン消費が跳ね上がるうえ、モデルが重要な制約を見落とす。
- **回避策**: `@file` で必要最小限の関連ファイルと型定義だけを指定し、会話が長くなったら **会話コンパクション** や新セッションへの切り替えを行う。

#### 失敗③：セキュリティ確認なしで業務コードを外部ツールへ投入する
- **起きること**: 個人アカウントの無料プランなどで業務コードを送信してしまい、学習利用や情報漏洩のインシデントになる。
- **回避策**: 業務利用前に必ず **ゼロデータ保持（ZDR）** 契約やエンタープライズプランの適用を確認し、機密要件が厳しい案件では **BYOK** または **ローカルファーストAI開発** を選択する。

### 3. 明日から試せる実践レシピ（3ステップ）

1. **まずは「プランモード」を1回挟む**: 次の機能実装やバグ修正で、いきなりコードを書かせず「まず原因仮説と変更予定ファイル一覧、実装計画だけを提示して」と指示してから着手する。
2. **タスク終了ごとにセッションを切り替える**: 1つのチケットが終わったらチャット履歴をリセットし、コンテキスト汚染を防ぎながら **コスト・トークン可視化** で1タスクあたりの消費感覚をつかむ。
3. **別タスクを「Git Worktree」で試す**: 大きめのリファクタリングやテスト追加をAIに任せている間に、別ブランチのWorktreeを切って自分の作業や別エージェントを並行稼働させてみる。

### 4. 理解度チェック・ミニクイズ

**Q1. 未知の大規模リポジトリで「既存コードに影響を与えずに仕様や依存関係だけを調べたい」場合、最も安全な動作モードはどれですか？**
<details>
<summary>解答と解説を見る</summary>

**答え：アスクモード（Ask Mode）**
ファイル編集やコマンド実行が禁止された読み取り専用モードのため、誤ってワークスペースを書き換えるリスクなしに安全な調査・設計相談ができます。

</details>

**Q2. エージェントとのやり取りが長くなり、コンテキスト上限に近づいて応答が遅く・高コストになってきました。作業の文脈を保ったまま継続するための機能は何ですか？**
<details>
<summary>解答と解説を見る</summary>

**答え：会話コンパクション（Compaction）**
長期化した対話履歴を要点サマリーへ自動要約することで、トークン消費と遅延を抑えつつコンテキスト枯渇を防いで作業を継続できます。

</details>

**Q3. 1つのリポジトリ上で、複数のAIエージェントに互いにファイルを競合させず別々のIssueを同時実装させたい場合、どのGit活用手法が有効ですか？**
<details>
<summary>解答と解説を見る</summary>

**答え：Git Worktree並列開発**
1つのGitリポジトリから独立した作業ツリーを複数切り出せるため、エージェント同士が同じ作業ディレクトリを上書きし合う衝突を防ぎながら並列開発できます。

</details>
