# 03_ツール・エコシステム（AI駆動型開発キーワード集）

AI駆動型開発（AI-Driven Development）を支えるIDE・CLIエージェント、MCP・外部連携基盤、LLM推論基盤、RAG・ベクトル検索、カスタムスキルや安全な実行環境まで、ツールとエコシステムに関する重要キーワード500語を体系的にまとめたリファレンスです。

---

## 1. AIネイティブIDE・エディタ・CLIエージェント（1〜100）

1. **AIネイティブIDE**: 設計段階からAIエージェントとの協働を前提に構築された統合開発環境。コード補完だけでなく自律的なファイル編集やテスト実行までを一貫して支援する。
2. **Cursor**: VS CodeをベースにAI機能を深く統合したエディタ。ComposerやTab補完により、複数ファイルにまたがる編集と高速なコード生成を実現する。
3. **Windsurf**: エージェント型フロー（Cascade）を中心に据えたAIネイティブIDE。開発者の操作履歴やプロジェクト文脈をリアルタイムに追跡し、自律的な実装を進める。
4. **GitHub Copilot**: GitHubとOpenAIが提供するAIコーディング支援ツール。エディタ上でのインライン補完、チャット、Pull Requestレビュー、自律エージェント機能を備える。
5. **GitHub Copilot Workspace**: GitHub Issueから仕様策定、実装計画、コード変更、テスト検証までを一気通貫で行うブラウザベースの開発環境。
6. **Claude Code**: Anthropicが提供するターミナル常駐型のエージェントCLI。リポジトリ全体を理解し、シェルコマンド実行やファイル編集、Git操作を自律的に行う。
7. **Codex CLI**: OpenAIが提供するオープンソースのコマンドライン型コーディングエージェント。ローカル環境でファイル変更やテスト実行を対話的・自律的に進める。
8. **Gemini CLI**: Googleが提供するターミナル向けAI開発エージェント。大規模コンテキストやツール連携を活かし、コードベース調査から実装・デバッグまでを支援する。
9. **Cline**: VS Code拡張として動作する自律型AIコーディングエージェント。ファイル編集やコマンド実行の承認フローを備え、多様なLLMプロバイダとMCPに対応する。
10. **Roo Code**: Clineから派生したVS Code向けAIエージェント拡張。カスタムモード切替や役割分担機能により、設計・実装・デバッグを柔軟に使い分けられる。
11. **Aider**: ターミナルからGitリポジトリを直接操作するAIペアプログラミングツール。変更内容を自動でコミットし、差分ベースで複数ファイルを協調編集する。
12. **Continue**: オープンソースのAIコードアシスタント拡張機能。VS CodeやJetBrains IDE上で任意の商用・ローカルLLMを接続して補完やチャットを行える。
13. **Zed AI**: Rust製の高速エディタZedに組み込まれたAI支援機能。インラインアシストやエージェントパネルを備え、低遅延な編集体験を提供する。
14. **Amazon Q Developer**: AWSが提供するAI開発支援サービス。コード生成や脆弱性スキャンに加え、Javaバージョンアップなどの大規模コード変換機能を持つ。
15. **JetBrains AI Assistant**: IntelliJ IDEAなどのJetBrains製品群に統合されたAI機能。IDEの静的解析・リファクタリング機能と連携し、精度の高い提案を行う。
16. **Junie**: JetBrainsが提供する自律型コーディングエージェント。IDE内のプロジェクト構造やビルド設定を活かし、タスク計画からテスト検証までを実行する。
17. **Devin**: 自律的にソフトウェアエンジニアリングタスクを完遂するAIエージェント環境。専用のブラウザ・エディタ・シェルを持ち、Issue対応やPR作成を行う。
18. **OpenHands**: 旧OpenDevinとして知られるオープンソースの自律型ソフトウェア開発エージェント基盤。コンテナ化されたサンドボックス上でコード編集や調査を実行する。
19. **SWE-agent**: GitHubのIssue解決に特化して設計された自律エージェントフレームワーク。エージェント専用インターフェース（ACI）を通じてリポジトリを効率的に操作する。
20. **Augment Code**: 大規模エンタープライズ向けコードベースに最適化されたAI開発支援ツール。高速なコンテキストエンジンにより、巨大なモノレポでも的確な提案を行う。
21. **Sourcegraph Cody**: Sourcegraphのコード検索基盤を活用したAIコーディングアシスタント。複数リポジトリ横断のコンテキスト参照と高精度なコード理解が強み。
22. **Tabnine**: プライバシー重視の設計とオンプレミス導入に対応するAIコード補完ツール。組織固有のコードベースに合わせたカスタマイズやライセンス保護機能を備える。
23. **Supermaven**: 超長文コンテキストと低遅延推論を特徴とするコード補完エンジン。過去の編集履歴を広く保持し、次の一手を高速に予測する。
24. **Kiro**: 仕様駆動開発（Spec-Driven Development）をワークフローに組み込んだAI IDE。要件定義・設計書・タスクリストを生成してから実装へ進める構成を採る。
25. **Trae**: エージェント実行モードとチャット支援を統合したAIネイティブIDE。複数ファイルの自動生成やプレビュー確認をシームレスに行える。
26. **Bolt.new**: ブラウザ内のWebContainers上でフルスタックアプリを即時生成・実行できるAI開発環境。プロンプトから環境構築とデプロイまでを短時間で完結させる。
27. **v0**: Vercelが提供するUI生成特化型のAI開発ツール。自然言語やデザイン画像からReact・Tailwind CSS・shadcn/uiベースのコンポーネントを生成する。
28. **Lovable**: 自然言語の対話からWebアプリケーションのフロントエンドとバックエンドを一括構築するAIビルダー。GitHub同期やSupabase連携に対応する。
29. **Replit Agent**: クラウドIDEのReplitに統合された自律開発エージェント。アプリの設計、パッケージ導入、DB構成、ホスティング公開までを自動で進める。
30. **Firebase Studio**: Googleが提供するクラウドベースのAI統合開発環境。テンプレート生成、Geminiによるコード支援、プレビュー、Firebaseデプロイを一元化する。
31. **Goose**: Block社が公開したオープンソースの拡張可能AIエージェント。MCPを通じてローカル開発ツールや外部サービスと連携し、開発タスクを自動化する。
32. **Amp**: エージェント中心の新しい開発体験を目指すコーディングツール。スレッド共有やサブエージェント実行により、チームでのAI活用を促進する。
33. **OpenCode**: ターミナル上で動作するオープンソースのAIコーディングエージェント。複数モデルへの柔軟な切り替えとTUIベースの軽快な操作性を提供する。
34. **Plandex**: 大規模で複雑な変更を段階的に計画・適用するCLI型AI開発ツール。サンドボックス上で差分を確認してから実ファイルへ反映できる。
35. **Mentat**: コマンドラインから複数ファイルの同時編集を支援するAIコーディングツール。変更差分を対話的にレビューしながら取り込める。
36. **PearAI**: オープンソースで開発されるAIネイティブコードエディタ。チャット、補完、検索などのAIツールを統合インターフェースにまとめる。
37. **Void Editor**: プライバシーとオープンソース性を重視したVS CodeフォークのAIエディタ。任意のAPIキーやローカルモデルを直接接続して利用できる。
38. **Codeium**: 高速な自動補完とチャット機能を提供するAIコーディング支援プラットフォーム。幅広いIDE・エディタ向けにプラグインを展開している。
39. **Qodo**: 旧CodiumAIとして知られるコード品質・テスト生成特化のAI開発ツール。ユニットテスト自動生成やPRレビュー支援により信頼性を高める。
40. **CodeRabbit**: Pull Requestに対して自動で詳細レビューを行うAIコードレビューツール。変更要約、潜在バグ指摘、改善提案をコメントとして投稿する。
41. **Greptile**: リポジトリ全体の依存関係をインデックス化してPRレビューや質問応答を行うAIツール。大規模コードベースの文脈を踏まえた指摘が可能。
42. **Graphite Diamond**: Stacked PRワークフローを提供するGraphiteに統合されたAIレビュー機能。小さな差分単位で迅速なフィードバックを返す。
43. **Ellipsis**: PRの自動コードレビューと指摘箇所の自動修正パッチ生成を行うAIツール。チームのコーディング規約に沿ったチェックを自動化できる。
44. **Sourcery**: PythonやJavaScript等のコード品質改善・リファクタリングに特化したAIレビュー支援ツール。エディタ統合とPRチェックの両面で利用される。
45. **Bito AI**: IDEプラグインやGit連携を通じてコード解説、テスト生成、PRレビューを提供する開発支援ツール。チーム向けガイドライン適用にも対応する。
46. **Pieces for Developers**: コードスニペットや開発中のコンテキストをローカル中心で管理・検索するAIワークフローツール。長期記憶のように過去作業を再利用できる。
47. **Warp AI**: Rust製モダンターミナルWarpに統合されたAIエージェント機能。自然言語からのコマンド生成、エラー原因解析、対話的な運用自動化を支援する。
48. **Wave Terminal**: ターミナルにファイルプレビューやWeb表示、AIチャットを統合したオープンソース端末。CLI作業と視覚的確認を同一画面で行える。
49. **Fig / Amazon Q CLI**: ターミナル入力の自動補完とAI支援を提供するCLI拡張。サブコマンドやオプションの候補表示に加え、自然言語からシェル操作を補助する。
50. **ShellGPT**: コマンドラインからLLMを呼び出し、シェルコマンド生成やパイプ処理を行う軽量CLIツール。スクリプト作成やログ解析を素早く行える。
51. **LLM CLI**: Simon Willison氏が開発する汎用コマンドラインLLM実行ツール。プラグイン機構で多様なモデルや埋め込み処理、ログ保存を統一的に扱える。
52. **Fabric**: 再利用可能なプロンプトパターン群をCLIパイプラインとして実行できるオープンソースフレームワーク。要約やコード分析などを標準化できる。
53. **Mods**: Charm社製のターミナル向けAIコマンドツール。標準入力をLLMへ渡して整形出力でき、UNIXパイプラインに自然に組み込める。
54. **avante.nvim**: Neovim上でCursorのようなAI支援体験を実現するプラグイン。選択範囲の編集提案や差分適用をVim操作のまま行える。
55. **CodeCompanion.nvim**: Neovim向けにチャット、インライン編集、エージェントワークフローを提供するプラグイン。複数のLLMアダプタとツール連携に対応する。
56. **gp.nvim**: NeovimからLLMへプロンプトを送信し、バッファ内編集やチャットを行える軽量プラグイン。柔軟なカスタマイズが可能。
57. **copilot.vim**: VimおよびNeovimでGitHub Copilotのインライン補完を利用するための公式プラグイン。キーバインドで補完候補の採用や切替を行える。
58. **minuet-ai.nvim**: Neovim向けのFill-in-the-Middle（FIM）コード補完プラグイン。複数のクラウド・ローカルモデルから高速に補完候補を取得する。
59. **gptel**: Emacs上でLLMとの対話やリージョン編集を行うクライアントパッケージ。Org-modeやMarkdownバッファと高い親和性を持つ。
60. **aidermacs**: Emacs内からAiderの編集セッションを快適に操作するための統合パッケージ。差分確認や対象ファイル管理をEmacs流儀で行える。
61. **インライン補完（Ghost Text）**: カーソル位置の後続コードを薄いテキストでリアルタイム予測表示する機能。Tabキー等で即座に確定でき、タイピング負荷を大幅に減らす。
62. **Fill-in-the-Middle（FIM）**: カーソル前後のコード文脈（PrefixとSuffix）を同時に参照し、中間部分を自然に補完する推論手法。コード補完モデルの基盤技術。
63. **Next Edit Prediction（次編集予測）**: 現在の編集内容から次に修正すべき箇所や移動先カーソル位置を先読み提案する機能。単なる追記を超えたリファクタリングを加速する。
64. **マルチファイル編集（Composer）**: 1つの指示から関連する複数ファイルの新規作成・更新・削除を一括で提案・適用する機能。機能追加や横断リファクタリングに不可欠。
65. **Diffプレビュー・ハンク承認**: AIが提案した変更を統一差分形式で可視化し、変更塊（ハンク）単位で採用・却下を判断できるUI機構。安全性を担保する。
66. **チェックポイント・ロールバック**: エージェントの各ステップ実行前にワークスペース状態をスナップショット保存し、問題発生時に即座に巻き戻せる機能。
67. **エージェントモード（Agentic Mode）**: ファイル検索、コード編集、コマンド実行、エラー修正を自律ループで反復する動作モード。人間の逐次指示なしに目標達成を目指す。
68. **プランモード（Plan Mode）**: コード変更に着手する前に要件整理と実装計画の作成・合意形成に専念する動作モード。手戻りや意図しない破壊的変更を防ぐ。
69. **アスクモード（Ask Mode）**: ファイル変更やコマンド実行を禁止し、コードベース解説や設計相談のみを行う読み取り専用モード。安全な調査に適する。
70. **コンテキストメンション（@シンボル）**: `@file` や `@folder`、`@docs` のようにプロンプト内で参照対象を明示指定するUI記法。モデルへ渡す情報を的確に制御できる。
71. **コードベースインデックス**: リポジトリ内のファイル構造・シンボル・埋め込みベクトルを事前構築し、AIが必要なコード片を高速検索できるようにする仕組み。
72. **LSP連携（Language Server Protocol）**: 型情報、定義ジャンプ、参照一覧、診断エラーなどの静的解析結果をAIエージェントへ提供する連携機能。幻覚を減らし精度を高める。
73. **ASTベースコード解析（Tree-sitter）**: ソースコードを抽象構文木として高速パースし、関数・クラス単位の構造抽出や正確な編集範囲特定を行う技術。
74. **ターミナル統合実行**: エージェントがIDE内蔵ターミナルでビルドやテストを実行し、標準出力・エラー出力を自動で読み取って次の修正へ活かす仕組み。
75. **自動エラー修正ループ**: コンパイルエラー、Lint警告、テスト失敗を検知すると、エージェントが原因分析とコード修正を成功するまで反復するワークフロー。
76. **ブラウザプレビュー統合**: IDE内や連携ブラウザで開発中アプリの表示確認・DOM検査・コンソールログ取得を行い、UI修正を自律化する機能。
77. **バックグラウンドエージェント**: ローカル作業を妨げずにクラウドや別プロセス上で非同期にタスクを進めるエージェント形態。Issue対応やテスト拡充を並列実行できる。
78. **クラウド開発環境（CDE）**: GitHub CodespacesやGitpodのようにクラウド上に再現性のある開発コンテナを提供する基盤。AIエージェントの実行基盤とも相性が良い。
79. **Git Worktree並列開発**: 1つのGitリポジトリから複数の作業ツリーを切り出し、複数のAIエージェントに独立ブランチで同時実装させる手法。
80. **ヘッドレスエージェント実行**: UIを介さずCLIやCIパイプライン上から非対話モードでエージェントを起動する実行方式。定期メンテナンスやバッチ修正に活用される。
81. **エージェントCLIのCI統合**: GitHub Actions等のCI上でコーディングエージェントを呼び出し、PRレビュー・ドキュメント更新・テスト修正を自動化する構成。
82. **SWE-bench**: 実在するオープンソースリポジトリのGitHub Issue解決能力を測る代表的なベンチマーク。コーディングエージェントの実務性能評価に広く用いられる。
83. **HumanEval**: 関数仕様とdocstringから正しいPythonコードを生成できるかを評価するベンチマーク。モデルの基礎的なコード生成能力を測る指標として定着している。
84. **LiveCodeBench**: データ汚染を防ぐため公開日時が新しい競技プログラミング問題などを継続収集して評価するコーディングベンチマーク。
85. **Aider Polyglot Benchmark**: 複数プログラミング言語にわたるコード編集・修正タスクでLLMとエージェントの実装力を比較する評価基準。
86. **Agent-Computer Interface（ACI）**: 人間向けUIではなく、AIエージェントが誤操作しにくく最小トークンで高精度に操作できるよう設計された専用コマンド・出力インターフェース。
87. **コンテキストウィンドウ管理**: モデルの最大入力トークン制限内で、関連度の高いコードや履歴を優先保持・圧縮して推論品質を維持する制御技術。
88. **会話コンパクション（Compaction）**: 長期化したエージェントとの対話履歴を要点サマリーへ自動要約し、コンテキスト枯渇を防ぎながら作業を継続する機能。
89. **プロンプトキャッシュ活用**: システムプロンプトや大規模コード文脈をプロバイダ側でキャッシュ再利用し、エージェントの反復ターンにおける遅延とコストを削減する手法。
90. **スマートモデルルーティング**: タスクの難易度や種別に応じて、軽量高速モデルと高性能推論モデルを自動で使い分ける制御機構。コストと品質を両立する。
91. **マルチモデル切替**: 同一のエディタやCLI上で用途・好みに応じてClaude、GPT、Gemini、ローカルモデルなどを自由に切り替えられる設計。
92. **BYOK（Bring Your Own Key）**: ツール提供元の課金枠だけでなく、開発者自身が保有するLLMプロバイダのAPIキーを設定して利用できる仕組み。
93. **ローカルファーストAI開発**: ソースコードを外部クラウドへ送信せず、端末内または社内ネットワーク完結でAI支援を実行する運用アプローチ。
94. **ゼロデータ保持（ZDR）**: LLMプロバイダ側でプロンプトやコードのログ保存・学習利用を一切行わない契約・設定モード。企業導入時のセキュリティ要件として重視される。
95. **コード帰属・ライセンス検査**: AI生成コードが既存オープンソースのライセンス条項に抵触しないかを照合・警告する機能。法務リスクの低減に役立つ。
96. **セマンティックDiff**: 単なる行単位のテキスト差分ではなく、構文や意味の変更（関数移動、リネーム等）を構造的に把握して提示する差分表示技術。
97. **マルチエージェント協調IDE**: 設計担当・実装担当・テスト担当など複数の専門エージェントをIDE内で並列稼働させ、成果物を統合する次世代開発スタイル。
98. **セッション再開・フォーク**: 中断したエージェントセッションを途中状態から再開したり、特定時点から別アプローチへ分岐（フォーク）して試行できる機能。
99. **コスト・トークン可視化**: セッションごと・タスクごとの入力/出力トークン数やキャッシュヒット率、推定課金額をリアルタイム表示するメトリクス機能。
100. **AIペアプログラミング**: 開発者がナビゲーター（方針決定・レビュー）を担い、AIがドライバー（実装・調査）を担う協働開発スタイル。生産性と設計品質の同時向上を図る。

## 2. MCP・ツール連携・外部API接続（101〜200）

101. **Model Context Protocol（MCP）**: Anthropicが提唱した、AIアプリケーションと外部ツール・データソースを標準化された形式で接続するためのオープンプロトコル。
102. **MCPサーバー**: ファイルシステム、DB、SaaS APIなどの機能やデータをMCP仕様に沿って公開し、AIクライアントからの要求を処理するサーバープログラム。
103. **MCPクライアント**: IDEやエージェント本体側に組み込まれ、MCPサーバーとの接続確立・機能発見・ツール呼び出しを仲介するコンポーネント。
104. **MCPホスト**: 複数のMCPクライアントを統括し、ユーザー承認やセキュリティ境界、コンテキスト統合を管理する実行側アプリケーション（IDEやデスクトップアプリ等）。
105. **MCP Tools**: MCPサーバーがAIに公開する実行可能な操作単位。入力スキーマに基づき、データ検索・ファイル操作・API実行などのアクションを提供する。
106. **MCP Resources**: MCPサーバーがURI形式で公開する読み取り対象データ（ドキュメント、設定、スキーマ、ログ等）。コンテキスト参照に用いられる。
107. **MCP Prompts**: MCPサーバー側で事前定義された再利用可能なプロンプトテンプレート。ユーザーやクライアントが引数付きで呼び出せる。
108. **MCP Sampling**: MCPサーバー側からクライアント経由でLLM推論を要求できる仕組み。サーバー内での自律的な要約や判断処理を可能にする。
109. **MCP Roots**: クライアントがMCPサーバーに対してアクセス許可範囲となるルートURI（ワークスペースディレクトリ等）を通知する仕様。
110. **stdioトランスポート**: ローカルで起動したMCPサーバーとクライアント間を標準入出力経由のJSON-RPCで通信する方式。構成が簡潔でローカルツール連携に広く使われる。
111. **Streamable HTTPトランスポート**: リモートMCPサーバーとの通信に用いられるHTTPベースの標準トランスポート。SSEによるストリーミング応答とステートレス/ステートフル運用に対応する。
112. **Server-Sent Events（SSE）**: サーバーからクライアントへ単方向にリアルタイムイベントをストリーミング配信するHTTP技術。初期のリモートMCPやLLMトークン配信で多用される。
113. **JSON-RPC 2.0**: MCPのメッセージ交換基盤として採用されている軽量なリモートプロシージャコール規約。リクエスト・レスポンス・通知をJSON形式で統一的に表現する。
114. **MCPレジストリ**: 公開・社内向けのMCPサーバーを検索・配布・バージョン管理するためのカタログ基盤。信頼できるサーバーの発見と導入を容易にする。
115. **MCP Inspector**: MCPサーバーのツール・リソース・プロンプトをブラウザ上から対話的にテストおよびデバッグできる公式開発ツール。
116. **FastMCP**: PythonやTypeScriptでデコレータ等を用いて簡潔にMCPサーバーを構築できる高水準フレームワーク。スキーマ生成やトランスポート設定を省力化する。
117. **MCP Gateway**: 複数のMCPサーバーへの接続を集約し、認証・認可・監査ログ・レート制限・ツールフィルタリングを一元管理するプロキシ基盤。
118. **OAuth 2.1（MCP認証）**: リモートMCPサーバーへの安全な接続に採用されている認証・認可フレームワーク。PKCEや動的クライアント登録により安全にトークンを取得する。
119. **Agent2Agent（A2A）プロトコル**: 異なるフレームワークやベンダーで構築されたAIエージェント同士が能力を発見し、タスクを委譲・協調するためのオープン通信規約。
120. **Agent Card**: A2Aプロトコルにおいて各エージェントが自身の機能、エンドポイント、認証要件、入出力形式を記述して公開するJSONメタデータ。
121. **Function Calling（Tool Use）**: LLMが自然言語応答の代わりに、事前定義された関数名と構造化JSON引数を出力して外部処理を呼び出す機能。
122. **並列ツール呼び出し（Parallel Tool Calling）**: 1回の推論ターンで複数の独立したツール呼び出しを同時に発行し、総レイテンシを大幅に短縮する実行方式。
123. **Structured Outputs（構造化出力）**: JSON Schemaなどの厳密な型制約に従ってLLMの出力を強制生成させる機能。API連携やワークフロー自動化でのパース失敗を防ぐ。
124. **JSON Schema制約**: ツール引数や構造化出力の型・必須項目・列挙値を定義する仕様。エージェントの入出力バリデーションの標準として機能する。
125. **ツール定義コンテキスト肥大化**: 多数のMCPサーバーやツールを同時接続することで、ツール説明だけでトークン枠が圧迫され推論精度が低下する課題。
126. **遅延ツールロード（Lazy Tool Loading）**: 起動時に全ツールの詳細スキーマを読み込まず、必要になった時点で動的に検索・取得してコンテキストを節約する設計手法。
127. **動的ツール検索（Tool Search）**: 数百以上のツール群からタスクに関連するツールだけをベクトル検索やキーワード検索で抽出してLLMへ提示する仕組み。
128. **GitHub MCPサーバー**: リポジトリ参照、Issue管理、Pull Request作成・レビュー、Actionsログ確認などをAIエージェントから直接操作できるようにするMCP実装。
129. **GitLab MCPサーバー**: GitLabのマージリクエスト、パイプライン、Issue、WikiをAIエージェントと連携させるためのMCPサーバー。

183. **ツール出力の切り詰め（Truncation）**: 外部APIやDBクエリが返した巨大なレスポンスを適切なサイズに要約・制限し、コンテキスト溢れとトークン浪費を防ぐ処理。

## 3. モデル・推論基盤・ローカルLLM・最適化（201〜300）

201. **フロンティアモデル**: 高度な推論、長文コード理解、マルチモーダル処理で最先端性能を示す大規模商用LLM群。複雑な設計や難度の高いデバッグの中核となる。
202. **推論特化モデル（Reasoning Model）**: 応答前に内部で段階的な思考トークンを生成し、アルゴリズム設計・デバッグ・仕様検証の精度を大幅に高めるモデル群。
203. **テスト時計算スケーリング（Test-Time Compute）**: 学習時だけでなく推論時に追加の計算資源（思考時間や探索パス）を投入することで、難問の正答率を引き上げるアプローチ。
204. **オープンウェイトモデル**: 学習済み重みパラメータが公開され、自社サーバーやローカル環境で自由に推論・ファインチューニングできるLLMの総称。
205. **コーディング特化モデル**: ソースコード、コミット差分、技術文書を中心に学習・調整され、補完・生成・リファクタリング性能を高めた専用モデル。
206. **小型言語モデル（SLM）**: 数十億パラメータ規模で軽量・高速に動作する言語モデル。ローカル端末での即時補完や定型分類タスクに低コストで活用される。
207. **Mixture of Experts（MoE）**: 入力トークンごとに一部の専門家ネットワークのみを活性化して計算するアーキテクチャ。巨大な知識容量と高速な推論を両立する。
208. **マルチモーダルLLM**: テキストだけでなく画像・UIスクリーンショット・PDF図表・音声・動画を統合理解できるモデル。デザイン実装や画面バグ解析に有効。
209. **長文コンテキストモデル**: 数十万〜数百万トークンを一度に処理できるLLM。リポジトリ全体や大量のログを丸ごと参照した横断分析を可能にする。
210. **Needle in a Haystack評価**: 超長文コンテキストの中に埋め込んだ単一の重要情報をモデルが正確に抽出できるかを測る長文記憶性能ベンチマーク。
211. **コンテキストロット（Context Rot）**: 入力コンテキストが長大化するにつれて、モデルの注意力が分散し指示遵守率や推論精度が劣化する現象。
212. **KVキャッシュ（Key-Value Cache）**: Transformerの自己注意機構で過去のトークン計算結果（KeyとValue）をメモリに保持し、次トークン生成を高速化する仕組み。
213. **プレフィックスキャッシュ（Prefix Caching）**: 複数リクエスト間で共通する冒頭プロンプトのKVキャッシュをサーバー側で再利用し、初回トークン応答時間を大幅に短縮する最適化。
214. **TTFT（Time To First Token）**: リクエスト送信から最初の1トークンが出力されるまでの遅延時間。対話型エディタやチャットUIの体感速度を左右する重要指標。
215. **TPOT（Time Per Output Token）**: 2トークン目以降が1トークン生成されるごとの平均所要時間。ストリーミング表示の滑らかさと完了速度を決定する。
216. **スループット（Tokens/sec）**: 推論基盤が1秒あたりに処理・生成できる総トークン数。並列エージェント実行やバッチ処理のスケール能力を測る指標。
217. **Ollama**: ローカルPC上でオープンウェイトLLMをコマンド1つでダウンロード・実行・API公開できる定番ランタイム。Mac・Linux・Windowsに対応する。
218. **llama.cpp**: C/C++で実装された高効率なローカルLLM推論エンジン。CPU・Apple Silicon・各種GPU上で量子化モデルを軽量に動作させる基盤。
219. **LM Studio**: ローカルLLMの検索、ダウンロード、量子化選択、チャットテスト、OpenAI互換ローカルAPI配信をGUIで行えるデスクトップアプリ。
220. **MLX / mlx-lm**: Apple Siliconのユニファイドメモリ構造に最適化された機械学習フレームワークおよびLLM推論ライブラリ。Mac環境で高い推論効率を発揮する。
221. **vLLM**: PagedAttentionによりGPUメモリ効率と高並列スループットを実現する本番向けLLM推論サーバー。OpenAI互換APIを標準提供する。
222. **PagedAttention**: OSの仮想メモリとページングの概念をKVキャッシュ管理に応用し、GPUメモリの断片化を防いで同時処理数を劇的に増やす技術。
223. **SGLang**: 構造化生成とRadixAttentionによる高速プレフィックス再利用を強みとする高性能LLMサービングフレームワーク。エージェント用途に強い。
224. **TensorRT-LLM**: NVIDIA GPU向けにモデルグラフをコンパイル・最適化し、極限の低遅延と高スループットを引き出す推論エンジン。
225. **Text Generation Inference（TGI）**: Hugging Faceが提供する本番運用向けLLM推論サーバー。連続バッチ処理やストリーミング、分散推論をサポートする。
226. **ExLlamaV2**: 量子化モデル（EXL2形式）をコンシューマー向けGPU上で高速推論することに特化したPython/C++ライブラリ。
227. **ONNX Runtime GenAI**: クロスプラットフォームなONNX形式の生成AIモデルをCPU・GPU・NPU上で統一的に推論実行するためのランタイム。
228. **WebLLM**: WebGPUを活用してブラウザ内だけでLLM推論を完結させるライブラリ。サーバー通信不要の完全クライアントサイドAIを実現する。
229. **Transformers.js**: Hugging FaceモデルをONNX Runtime Web経由でブラウザやNode.js上で直接実行できるJavaScriptライブラリ。
230. **GGUF形式**: llama.cppエコシステムで標準採用されている単一ファイル形式のモデルフォーマット。メタデータと各種量子化重みを効率よく格納する。
231. **Safetensors**: Pickle実行による任意コード実行リスクを排除し、ゼロコピーで高速かつ安全にモデル重みを読み込める標準ファイル形式。
232. **量子化（Quantization）**: モデルの重みや活性化値をFP16からINT8・INT4・FP8など低ビット精度へ変換し、VRAM消費量と推論遅延を大幅に削減する圧縮技術。
233. **AWQ（Activation-aware Weight Quantization）**: 活性化分布に基づいて重要な重みを保護しながら4ビット量子化を行い、精度劣化を最小限に抑える手法。
234. **GPTQ**: キャリブレーションデータを用いて層ごとに誤差補正しながら重みを低ビット量子化するポストトレーニング量子化手法。
235. **K-Quants / I-Quants**: llama.cppで採用されているブロック単位の混合精度量子化方式（Q4_K_M、IQ4_XS等）。ファイルサイズと出力品質のバランスに優れる。
236. **FP8推論**: NVIDIA H100以降のGPU等でネイティブサポートされる8ビット浮動小数点推論。品質劣化をほぼ抑えつつ演算速度とメモリ効率を約2倍に高める。
237. **投機的デコーディング（Speculative Decoding）**: 軽量なドラフトモデルで複数トークンを先読み生成し、本体モデルで一括検証することで出力品質を変えずに推論を高速化する技術。
238. **Medusa / EAGLE**: モデル本体に追加の予測ヘッドを付与して複数トークンを並列予測する、自己完結型の投機的デコーディング手法。
239. **連続バッチ処理（Continuous Batching）**: リクエストの完了を待たずに空きスロットへ新規リクエストを動的に投入し、GPU稼働率を最大化するスケジューリング方式。
240. **Prefill-Decode分離（Disaggregated Serving）**: 計算律速な入力処理（Prefill）とメモリ帯域律速な生成処理（Decode）を別GPUノードに分離し、遅延干渉を防ぐアーキテクチャ。
241. **FlashAttention**: GPUの高速なSRAMを最大限活用してAttention計算のHBMメモリアクセスを削減し、長文処理の高速化と省メモリ化を両立するアルゴリズム。
242. **テンソル並列（Tensor Parallelism）**: 1つの層の行列演算を複数GPUに分割して同時実行し、単一GPUに収まらない大規模モデルの推論遅延を短縮する分散手法。
243. **パイプライン並列（Pipeline Parallelism）**: モデルの層を複数GPUやノードへ直列配置し、マイクロバッチ単位でリレー処理することで超大規模モデルを動かす分散手法。
244. **VRAM容量・メモリ帯域幅**: ローカルLLMや推論サーバーの性能を決定づけるハードウェア指標。モデル重みとKVキャッシュの収容力・生成速度に直結する。
245. **ユニファイドメモリ**: CPUとGPUが同一の物理メモリ空間を共有する設計（Apple Silicon等）。大容量メモリをそのまま大規模モデルの推論に活用できる。
246. **NPU（Neural Processing Unit）**: ノートPCやモバイル端末に搭載されるAI推論専用アクセラレータ。低消費電力で常駐AIやオンデバイス推論を処理する。
247. **専用AI推論チップ（LPU / WSE / TPU）**: GroqのLPU、CerebrasのWSE、GoogleのTPUなど、LLM推論の超高速化や大規模計算に特化して設計されたハードウェア群。
248. **サーバーレスGPU推論**: Modal、RunPod、Replicate、Together AIのように、リクエスト発生時だけGPUコンテナを起動し従量課金でモデル推論できるクラウド基盤。
249. **Amazon Bedrock**: AWS上でClaudeやLlamaなど複数の基盤モデルを統一API・VPC閉域・IAM権限制御のもとで安全に利用できるマネージドサービス。
250. **Google Cloud Vertex AI**: Geminiやオープンモデルをエンタープライズ環境で推論・調整・評価・デプロイできるGoogle Cloudの統合AIプラットフォーム。
251. **Azure AI Foundry**: Azure上でOpenAIモデルや各種オープンモデルを企業ガバナンス、プライベートエンドポイント、コンテンツ安全フィルタ付きで運用する基盤。
252. **Hugging Face Hub**: オープンソースのモデル、データセット、デモアプリ（Spaces）が集積するAIエコシステム最大のリポジトリプラットフォーム。
253. **モデルカード（Model Card）**: モデルの学習方針、対応言語、ベンチマーク結果、ライセンス、既知の制約やリスクを明文化した仕様ドキュメント。
254. **LoRA（Low-Rank Adaptation）**: 事前学習モデルの重みを凍結し、少数の低ランク行列アダプタのみを追加学習することで低コストにドメイン適応する微調整手法。
255. **QLoRA**: 4ビット量子化したベースモデル上でLoRA学習を行い、単一GPUでも大規模モデルのファインチューニングを可能にする省メモリ手法。
256. **蒸留（Knowledge Distillation）**: 高性能な大規模教師モデルの出力や推論過程を軽量な生徒モデルに学習させ、低コスト・高速ながら高い精度を実現する技術。
257. **教師ありファインチューニング（SFT）**: 高品質な入出力ペアデータを用いて、特定のコーディング規約やAPI形式、応答スタイルをモデルへ直接学習させる工程。
258. **DPO（Direct Preference Optimization）**: 報酬モデルを別途学習せずに、好ましい応答と好ましくない応答のペアから直接モデルをアライメントする最適化手法。
259. **RLVR（検証可能報酬による強化学習）**: ユニットテストの成否やコンパイル通過など機械的に検証可能な報酬を用いて、モデルのコーディング・推論能力を強化する学習手法。
260. **Unsloth**: メモリ使用量を大幅削減し、通常の数倍の速度でLLMのLoRA/QLoRAファインチューニングを実行できる最適化ライブラリ。
261. **Axolotl**: YAML設定ファイルを中心に多様なデータセット形式・分散学習・LoRA/フルファインチューニングを統一実行できる学習フレームワーク。
262. **トークナイザー（Tokenizer）**: テキストやソースコードをモデルが処理可能なサブワードID列へ変換するモジュール。コードのインデントや日本語のトークン効率に大きく影響する。
263. **Byte-Pair Encoding（BPE）**: 頻出する文字ペアを反復統合して語彙を構築する代表的なトークン分割アルゴリズム。多くの主要LLMで採用されている。
264. **トークン効率（日本語・コード）**: 同じ意味の文章やコードをどれだけ少ないトークン数で表現できるかの指標。API課金額、推論速度、実質コンテキスト長に直結する。
265. **Temperature（温度パラメータ）**: 次トークン選択時の確率分布の鋭さを調整する設定。コード生成や厳密なJSON出力では低く（0〜0.2）、発想支援では高めに設定する。
266. **Top-p（Nucleus Sampling）**: 累積確率が閾値pに達する上位候補トークン集合のみからサンプリングする制御パラメータ。出力の多様性と安定性のバランスを取る。
267. **Reasoning Effort（推論強度制御）**: 推論モデルに対して思考トークンに費やす計算量（low / medium / high等）をタスク難度に応じて動的指定できるAPIパラメータ。
268. **制約付きデコーディング（Constrained Decoding）**: 文法（CFG）や正規表現、JSON Schemaに適合しないトークンの生成確率をマスクし、100%構文正当な出力を保証する技術。
269. **Outlines / Guidance**: 有限状態マシンを用いてLLM出力を正規表現・型・テンプレートへ厳密に制約しながら高速生成するライブラリ群。
270. **Batch API（非同期バッチ推論）**: リアルタイム応答が不要な大量のコード解析やテスト生成を非同期ジョブとして投入し、通常より大幅に安い単価で処理するAPI形態。
271. **プロビジョンドスループット（PTU）**: 一定量の推論トークン帯域を事前予約確保する契約形態。大規模チームや本番サービスで安定した低遅延とレート保証を得るために用いる。
272. **モデルフォールバック**: 主系モデルのレート制限超過や障害発生時に、自動的に待機モデルや別プロバイダへ切り替えて開発・本番処理の停止を防ぐ冗長化設計。
273. **レイテンシバジェット**: 補完は200ms以内、チャット初回応答は2秒以内のように、UX要件から逆算してモデル選定やキャッシュ戦略を決める設計指標。
274. **コンテキストキャッシング（Explicit Caching）**: 大規模な仕様書やコードベースを明示的にキャッシュ登録し、TTL期間中の複数クエリでトークンコストと計算時間を削減するAPI機能。
275. **セマンティックキャッシュ**: 完全に同一の文字列でなくとも意味的に類似したプロンプトの過去応答をベクトル類似度で再利用し、API呼び出しを削減するキャッシュ層。
276. **推論ルーター（Model Router）**: 入力プロンプトの複雑度を軽量分類器で判定し、単純タスクは小型モデル、難問は大型モデルへ振り分けるコスト最適化コンポーネント。
277. **ローカルフォールバック構成**: オフライン環境や機密リポジトリ作業時のみ自動的にOllama等のローカルモデルへ切り替えるハイブリッド運用構成。
278. **モデルバージョン固定（Pinning）**: `latest` エイリアスではなく具体的なスナップショットIDを指定し、モデル更新による予期せぬ出力変化や回帰を防ぐ運用ベストプラクティス。
279. **モデル廃止・移行管理（Deprecation）**: クラウドLLMの提供終了スケジュールを監視し、後継モデルへの評価ベンチマーク実行と安全な切替を計画するライフサイクル管理。
280. **OpenAI互換API標準**: `/v1/chat/completions` や `/v1/embeddings` 等のエンドポイント仕様を事実上の共通インターフェースとして採用し、推論基盤の差し替えを容易にする慣行。
281. **Responses API**: 単発のチャット補完を超え、サーバー側状態管理、組み込みツール、推論アイテム保持を統合的に扱う次世代のモデル呼び出しAPI設計。
282. **ストリーミング応答（Streaming）**: 全文生成の完了を待たずトークン単位で逐次返却する通信方式。体感待ち時間を削減し、途中キャンセルや進捗表示を可能にする。
283. **トークン使用量アカウンティング**: プロンプト・出力・キャッシュ読込・思考トークンの内訳をプロジェクトやユーザー単位で集計し、FinOpsとして予算管理する仕組み。
284. **プロンプト圧縮（LLMLingua等）**: 意味を保ちながら冗長なトークンを軽量モデルで間引き、長いコンテキストを少ないトークン数へ圧縮して投入する技術。
285. **マルチモーダルビジョンエンコーダ**: スクリーンショットやワイヤーフレーム画像をパッチトークン列へ変換し、LLMがレイアウト崩れやUI要素を認識できるようにする構成要素。
286. **音声リアルタイムAPI（Realtime API）**: 音声入力から音声出力までを低遅延で直接処理するマルチモーダルAPI。ハンズフリーの設計壁打ちやペアプロ応用に活用される。
287. **合成データ生成（Synthetic Data）**: 高性能モデルを用いてコード修正例やテストケース、評価用Q&Aを大量生成し、小型モデルの蒸留やテスト基盤拡充に活用する手法。
288. **LLM-as-a-Judge**: 別の高性能LLMを評価者として用い、生成コードの可読性や仕様準拠度、回答品質をルーブリックに基づいて自動採点する評価手法。
289. **プロンプト回帰テスト（Promptfoo）**: プロンプト変更やモデル切替が既存タスクの品質を劣化させていないかを、複数ケースとアサーションで自動検証するCLI/CIツール。
290. **A/Bモデル評価（Arena方式）**: 複数モデルの出力を匿名で並べて比較・投票し、実務ユースケースに最も適したモデルを選定する評価アプローチ。
291. **ハルシネーション率測定**: 存在しないAPI名・パッケージ・設定オプションをモデルが捏造する頻度を定量計測し、モデル選定やグラウンディング改善に活かす指標。
292. **コンテキスト利用率最適化**: モデルの入力上限を闇雲に埋めるのではなく、精度が最大化する適正トークン帯（スイートスポット）に収めるチューニング指針。
293. **出力トークン上限管理（Max Tokens）**: 意図しない無限ループ出力や長大ファイル生成による途中途切れ・課金暴走を防ぐため、タスク別に適切な上限を設定する制御。
294. **ストップシーケンス（Stop Sequences）**: 特定の文字列が出現した時点で生成を即座に終了させるパラメータ。FIM補完や構造化コード片の抽出精度を高める。
295. **シード固定（Deterministic Seed）**: 乱数シードを指定して可能な限り再現性のある出力を得る機能。デバッグや自動評価パイプラインの安定化に役立つ。
296. **ログ確率（Logprobs）**: 生成された各トークンの確信度を対数確率として取得する機能。信頼度スコアリングや分類タスクの不確実性検知に利用される。
297. **マルチLoRAサービング**: 単一のベースモデル重みをGPUに常駐させたまま、リクエストごとに異なるタスク・顧客向けのLoRAアダプタを動的切替して推論する技術。
298. **モデルマージング（Model Merging）**: 複数のファインチューニング済みモデルの重みをTIESやDARE等の手法で統合し、追加学習なしで複合能力を引き出す技術。
299. **MoEルーター最適化**: エキスパート間の負荷偏りを抑えつつ、推論サーバー上で活性化されたエキスパートのみを効率よく配置・実行するシステム最適化。
300. **ハイブリッド推論アーキテクチャ**: 補完や機密コード解析はローカル/オンプレミス推論、複雑な設計や横断調査はクラウドフロンティアモデルへ振り分ける実践的構成。

## 4. RAG・ベクトル検索・ナレッジ基盤（301〜400）

301. **RAG（Retrieval-Augmented Generation）**: 外部のドキュメントやコードベースから関連情報を検索・取得し、プロンプトへ注入して根拠ある回答を生成するアーキテクチャ。
302. **Agentic RAG**: 固定的な1回検索ではなく、エージェント自身が検索クエリの再作成・追加検索・ソース選択・十分性判定を反復する自律型RAG構成。
303. **GraphRAG**: 文書からエンティティと関係性を抽出した知識グラフを構築し、複数文書にまたがる大局的な構造理解やマルチホップ推論を行うRAG手法。
304. **LightRAG**: GraphRAGの計算コストを抑えつつ、エンティティレベルとテーマレベルの二層検索で高速・高精度な知識統合を行う軽量グラフRAG実装。
305. **Corrective RAG（CRAG）**: 検索結果の関連度を評価し、不十分な場合はWeb検索やクエリ書き換えへ自動フォールバックして回答品質を補正するパターン。
306. **Self-RAG**: モデル自身が「検索が必要か」「取得文書は関連しているか」「生成文は根拠に裏付けられているか」を自己評価トークンで制御する手法。
307. **HyDE（Hypothetical Document Embeddings）**: ユーザーの質問から仮想の回答文書を一度生成し、その埋め込みベクトルで検索することで質問と文書の語彙ギャップを埋める技術。
308. **埋め込みモデル（Embedding Model）**: テキストやソースコードの意味を固定次元の数値ベクトル空間へ写像するモデル。意味検索や類似度判定の基盤となる。
309. **コード特化埋め込みモデル**: 関数定義、識別子、構文構造、自然言語コメント間の対応関係に最適化された埋め込みモデル。コードベース検索の再現率を高める。
310. **マルチモーダル埋め込み**: テキストと画像（設計図、UI画面、グラフ等）を共通のベクトル空間へ埋め込み、横断的に検索できるようにする表現技術。
311. **Matryoshka Representation Learning（MRL）**: 精度を大きく落とさずに埋め込みベクトルの次元数を先頭から柔軟に切り詰められる学習手法。ストレージと検索速度を最適化できる。
312. **バイナリ量子化（ベクトル）**: 浮動小数点ベクトルを1ビット表現へ圧縮し、ハミング距離による超高速検索とメモリ使用量の大幅削減を実現する技術。
313. **スカラー量子化（SQ）**: ベクトルの各次元をFP32からINT8等へ圧縮し、検索精度を維持しながらベクトルDBのRAMコストを約4分の1に抑える手法。
314. **直積量子化（Product Quantization / PQ）**: 高次元ベクトルを部分空間に分割して代表コードブックへ圧縮し、大規模データセットでの近似最近傍探索を省メモリ化する技術。
315. **近似最近傍探索（ANN）**: 厳密な全件比較の代わりにグラフやクラスタ構造を用いて、ミリ秒単位で類似ベクトルを高速検索するアルゴリズム群。
316. **HNSW（Hierarchical Navigable Small World）**: 多層グラフ構造を用いて高い再現率と高速な検索性能を両立する、ベクトルDBで最も広く採用されているANNインデックス手法。
317. **IVF（Inverted File Index）**: ベクトル空間をクラスタ分割し、クエリに近いクラスタ内だけを探索することで大規模インデックスの計算量を削減する手法。
318. **DiskANN**: SSDストレージを前提に設計されたグラフベースANNインデックス。巨大なベクトル集合をRAMに載せきれない規模でも低コスト・低遅延で検索できる。
319. **コサイン類似度**: 2つのベクトル間の角度の近さを測る距離指標。文書長の影響を受けにくく、テキストやコードの意味類似度計算の標準として使われる。
320. **内積（Dot Product）とL2距離**: ベクトルの大きさと方向を反映する類似度・距離指標。正規化済み埋め込みではコサイン類似度と等価かつ高速に計算できる。
321. **pgvector**: PostgreSQLにベクトル型とHNSW/IVFFlatインデックスを追加する拡張機能。既存のRDBトランザクションや権限制御と統合したRAG構築に人気。
322. **pgvectorscale**: PostgreSQL上でDiskANN系のStreamingDiskANNインデックスと統計的バイナリ量子化を提供し、大規模ベクトル検索を高速化する拡張。
323. **Qdrant**: Rust製の高性能オープンソースベクトルデータベース。豊富なペイロードフィルタリング、スパースベクトル対応、量子化機能を備える。
324. **Milvus**: 分散アーキテクチャで数十億規模のベクトルを扱えるクラウドネイティブ・オープンソースベクトルDB。ハイブリッド検索とGPU高速化に対応する。
325. **Pinecone**: フルマネージドなサーバーレスベクトルデータベース。運用負荷を抑えながら名前空間分離やリアルタイム更新、高速ANN検索を提供する。
326. **Weaviate**: ベクトル検索とBM25キーワード検索、マルチテナント管理、スキーマベースのデータモデリングを統合したオープンソースAIデータベース。
327. **Chroma**: Python/TypeScriptから数行で導入できる軽量なオープンソース埋め込みデータベース。プロトタイピングから小中規模RAGまで広く使われる。
328. **LanceDB**: Apache ArrowとLanceカラムナーフォーマットを基盤とする埋め込み型ベクトルDB。ローカルファイルやオブジェクトストレージ上でサーバーレスに高速動作する。
329. **Elasticsearch / OpenSearch（ベクトル対応）**: 全文検索エンジンにHNSWベクトル検索とRRF統合を組み合わせ、既存検索基盤をそのままハイブリッドRAGへ拡張できる構成。
330. **FAISS**: Metaが開発した高速ベクトル類似度検索・クラスタリングライブラリ。インメモリおよびGPU上での大規模バッチ検索基盤として定番。
331. **ハイブリッド検索（Hybrid Search）**: 意味を捉える密ベクトル検索（Dense）と、識別子・エラーコードに強いキーワード検索（Sparse/BM25）を組み合わせる検索方式。
332. **BM25**: 単語の出現頻度と逆文書頻度・文書長補正に基づく古典的な全文検索ランキングアルゴリズム。関数名やエラーIDの厳密一致でベクトル検索の弱点を補う。
333. **スパースベクトル（SPLADE / BGE-M3）**: ニューラルモデルで語彙拡張した疎ベクトルを生成し、従来のキーワード検索より意味理解に優れた高精度検索を実現する手法。
334. **Reciprocal Rank Fusion（RRF）**: ベクトル検索とBM25など複数の検索ランキング結果を順位の逆数和で統合し、スコア尺度の違いを意識せず安定融合するアルゴリズム。
335. **リランカー（Reranker / Cross-Encoder）**: 初期検索で抽出した上位候補（例：50件）をクエリとペアで精密に再採点し、最も関連性の高い数件へ絞り込む二段階検索コンポーネント。
336. **ColBERT（Late Interaction）**: トークン単位の複数ベクトル表現を保持し、検索時にMaxSim演算で細粒度に照合する高精度・高効率なリトリーバル手法。
337. **チャンキング（Chunking）**: 長大なドキュメントやソースコードを埋め込み・検索に適した意味単位の断片へ分割する前処理工程。RAG精度を大きく左右する。
338. **固定長チャンキングとオーバーラップ**: 指定トークン数ごとに分割し、境界での文脈分断を防ぐため前後の一部を重複（オーバーラップ）させて保持する基本手法。
339. **再帰的文字分割（Recursive Character Splitting）**: 見出し・段落・改行・文の区切りを優先順位順に適用し、文書構造をなるべく保ったまま指定サイズ以内へ分割する手法。
340. **ASTベースコードチャンキング**: Tree-sitter等を用いて関数・メソッド・クラス・モジュール境界に沿ってソースコードを分割し、構文的に完結したコード片を検索対象とする手法。
341. **セマンティックチャンキング**: 隣接する文同士の埋め込み類似度の変化点を検出し、話題が切り替わる位置で自動的にチャンク分割する手法。
342. **Contextual Retrieval（文脈付与検索）**: 各チャンクをインデックス登録する前に、文書全体における位置づけや背景説明を短文で先頭付与し、検索失敗率を劇的に下げる手法。
343. **親子チャンキング（Parent-Child / Small-to-Big）**: 検索精度の高い小さなチャンクでヒットさせた後、LLMへは前後の文脈を含む親チャンクやセクション全体を渡す設計パターン。
344. **メタデータフィルタリング**: 言語、リポジトリ名、ファイルパス、更新日時、権限ロールなどの属性条件で検索対象を事前絞り込みする機能。
345. **クエリ拡張（Multi-Query Retrieval）**: ユーザーの単一質問をLLMで複数表現や観点へ展開して並列検索し、言い換えによる取りこぼしを防ぐ手法。
346. **クエリ分解（Query Decomposition）**: 複合的な質問を複数の独立したサブ質問へ分割して個別に検索・回答し、最終結果を統合する手法。
347. **ステップバックプロンプティング**: 具体的な細部質問から一段抽象化した上位概念クエリも同時検索し、背景原理を踏まえた正確な回答を導く技術。
348. **メタデータ自動抽出**: ドキュメント取り込み時にタイトル、要約、対象コンポーネント、キーワード、想定質問などをLLMで自動生成し検索インデックスを強化する処理。
349. **LlamaIndex**: データ取り込み、インデックス構築、ハイブリッド検索、エージェントRAGを包括的に支援する代表的なデータフレームワーク。
350. **Unstructured**: PDF、Word、HTML、PowerPoint、メールなど多様な非構造化ファイルからレイアウトを保ってテキスト・表を抽出する前処理ツール。
351. **Docling**: IBMが公開した高精度ドキュメント解析ライブラリ。複雑なPDFの段組み・数式・表構造をクリーンなMarkdownやJSONへ変換できる。
352. **Marker / MinerU**: 技術論文や仕様書PDFからMarkdown・LaTeX・表・図を高速かつ高精度に抽出するオープンソース変換ツール群。
353. **OCR・レイアウト解析（Vision PDF解析）**: スキャンPDFやアーキテクチャ図を含む資料をビジョンモデルで構造認識し、RAGで検索可能なテキスト・説明へ変換する処理。
354. **増分インデックス更新（Incremental Indexing）**: 全文再インデックスを避け、Git差分やハッシュ比較で変更されたファイル・チャンクのみを差分更新するデータパイプライン設計。
355. **ドキュメント鮮度管理（TTL / バージョニング）**: 古い仕様書や廃止APIドキュメントが最新情報と混在しないよう、バージョンタグや有効期限で検索優先度を制御する運用。
356. **アクセス制御付きRAG（Permission-Aware RAG）**: 検索ユーザーのACL（アクセス制御リスト）や所属ロールに基づき、閲覧権限のある文書のみを検索結果に含めるセキュリティ設計。
357. **データソースコネクタ（ETL / Airbyte）**: Notion、Confluence、Slack、Google Drive、GitHub等から定期同期でナレッジを自動収集するデータ統合基盤。
358. **コードグラフ（Code Knowledge Graph）**: 関数呼び出し関係、継承階層、モジュール依存、型定義をグラフ構造として保持し、影響範囲調査や設計理解を支援する基盤。
359. **リポジトリマップ（Repo Map）**: プロジェクト内の主要ファイルと公開シンボル（クラス・関数シグネチャ）を凝縮一覧化し、少ないトークンで全体俯瞰を与える手法。
360. **Agentic Search（Grep / Glob検索）**: 事前ベクトルDBに頼らず、ripgrep・fd・AST検索ツールをエージェントが直接組み合わせて最新ソースコードを正確に探索するアプローチ。
361. **ripgrep（rg）**: Rust製の超高速正規表現コード検索CLI。`.gitignore` を尊重しながら大規模リポジトリを瞬時に横断でき、ほぼ全てのCLIエージェントの標準検索ツールとなる。
362. **ast-grep（sg）**: 抽象構文木パターンを用いて構造的にコード検索・一括リライトを行える高速CLIツール。単なる文字列置換より安全で正確。
363. **Zoekt**: トライグラムインデックスを用いて巨大な複数リポジトリ群をミリ秒単位で全文・正規表現検索できるオープンソースコード検索エンジン。
364. **Sourcegraph**: 大規模組織の複数リポジトリを横断検索・コードナビゲーション・バッチ変更できるコードインテリジェンス基盤。
365. **llms.txt**: Webサイトやドキュメントサイトのルートに配置し、AIエージェントが重要ページの構成とMarkdown本文を効率よく取得できるようにする標準提案ファイル。
366. **RAGAS**: 文脈適合性、忠実性（Faithfulness）、回答関連性などの指標を自動算出し、RAGパイプラインの品質を定量評価するフレームワーク。
367. **TruLens**: RAGの「RAG Triad（文脈関連性・根拠性・回答関連性）」をトレース単位で可視化・評価し、ボトルネックを特定する評価ツール。
368. **DeepEval**: ユニットテスト感覚（pytest統合）でRAGやエージェントの忠実性・幻覚・毒性・指標回帰をCI上で自動テストできる評価フレームワーク。
369. **グラウンディング（Grounding）**: モデルの生成内容を検索取得した一次ソースへ厳密に紐づけ、根拠のない推測や捏造を抑止する設計原則。
370. **インライン引用（Citation）**: 生成された説明やコード提案の根拠となったファイルパス・行番号・仕様書URLを明示し、開発者が即座に裏取りできるようにする出力形式。
371. **ゴールデンデータセット（RAG評価用）**: 質問・正解根拠チャンク・期待回答をペアにした検証用データセット。検索アルゴリズムやチャンク戦略の変更効果を客観測定する。
372. **Recall@K / Precision@K**: 検索上位K件の中に正解文書がどれだけ含まれるか（再現率）と、上位K件のうち何割が関連文書か（適合率）を測る基本検索指標。
373. **MRR（Mean Reciprocal Rank）**: 最初の正解文書が検索結果の何位に現れたかの逆数平均。最上位に正確な根拠を提示できるかを測る指標。
374. **NDCG（Normalized Discounted Cumulative Gain）**: 関連度の高い文書がより上位にランクされているかを段階評価で数値化するランキング品質指標。
375. **Lost in the Middle現象**: 長いプロンプトの中央付近に配置された検索チャンクが、先頭や末尾に比べてモデルに無視されやすくなる既知の特性。
376. **コンテキスト再配列（LongContextReorder）**: Lost in the Middle対策として、関連度の高いチャンクをプロンプトの先頭と末尾に配置するよう並び替える後処理手法。
377. **Mem0**: ユーザー・セッション・エージェント単位の長期記憶を自動抽出・統合・更新・検索できるオープンソースのメモリレイヤー基盤。
378. **Letta（旧MemGPT）**: OSの仮想メモリ管理のように、コンテキスト内の短期記憶と外部ストレージの長期記憶をエージェント自身が編集・ページングするアーキテクチャ。
379. **Zep**: 会話履歴や業務データから時間軸付きの知識グラフ（Temporal Knowledge Graph）を自動構築し、最新状態を正確に引き出せるエージェント記憶基盤。
380. **エピソード記憶（Episodic Memory）**: エージェントが過去のタスクで経験したエラー解決手順や成功パターンを事例として蓄積し、類似課題で再利用する記憶層。
381. **意味記憶（Semantic Memory）**: プロジェクトのアーキテクチャ規約、用語集、API仕様など普遍的な事実知識を構造化して保持する記憶層。
382. **手続き記憶（Procedural Memory）**: テスト手順、リリース作業、マイグレーション方法など「どう実行するか」の定型ワークフローを蓄積する記憶層。
383. **セッションログ・トランスクリプト検索**: 過去のエージェント対話ログを構造化保存・検索可能にし、以前の設計判断や調査結果を即座に参照できるようにする仕組み。
384. **ADR（Architecture Decision Record）ナレッジ化**: 設計意思決定の背景・採用理由・却下案をADRとしてリポジトリ管理し、AIが文脈を外した提案をしないよう参照させる運用。
385. **コードベースWiki自動生成（DeepWiki等）**: リポジトリの構造・モジュール間関係・データフローをAIが自動解析して体系的なWikiドキュメントへまとめるツール群。
386. **Docs-as-Code（AI最適化）**: 設計書やAPI仕様をMarkdown・Mermaid等でコードと同じGitリポジトリに配置し、PRと同時更新することでAI参照鮮度を保つ開発文化。
387. **コンテキスト最小化ドキュメント**: フォルダ構成、主要スキーマ、ロードマップ、作業履歴を簡潔なMarkdownに集約し、AIの探索トークン消費を大幅削減する運用手法。
388. **トークン予算配分（Context Budgeting）**: システム指示、ルール、検索結果、コード片、会話履歴のそれぞれに上限トークン比率を割り当てて品質を安定させる制御。
389. **多言語クロスリンガル検索**: 日本語の自然言語クエリで英語のソースコードや公式ドキュメントを高精度にヒットさせる多言語埋め込み活用手法。
390. **テーブル・スキーマRAG（Text-to-SQL支援）**: DBのDDL定義、カラム説明、サンプル値、結合例を検索対象とし、正確なSQL生成を支えるメタデータRAG設計。
391. **エラーログ・インシデントRAG**: 過去の障害報告書、ポストモーテム、修正コミットをインデックス化し、新規エラー発生時に類似原因と対処案を即提示する仕組み。
392. **チャンク重複排除（Deduplication）**: コピー文書や自動生成コード、ロックファイル等の重複・ノイズをインデックス前に除外し、検索枠の汚染を防ぐ前処理。
393. **ノイズファイル除外（.aiignore / .ragignore）**: ビルド成果物、依存パッケージ、バイナリ、機密ファイル等をインデックスおよびAI参照対象から明示的に除外する設定。
394. **ハイブリッドインデックス同期**: 全文検索インデックスとベクトルインデックスの更新をトランザクショナルまたは冪等バッチで同期し、検索結果の不整合を防ぐ運用。
395. **コールドスタート・ウォームアップ**: サーバーレスベクトルDBや大規模インデックスの初回検索遅延を抑えるため、キャッシュ事前読み込みを行う最適化。
396. **マルチテナント名前空間分離**: プロジェクトや顧客組織ごとにベクトルDBのNamespace/Collectionを厳格分離し、データ越境参照を物理的・論理的に防ぐ設計。
397. **埋め込みモデル移行（Re-embedding）**: より高精度な埋め込みモデルへ切り替える際、別インデックスへ並列再構築して無停止切替（Blue/Green）する運用パターン。
398. **ナレッジグラフ可視化**: エンティティやモジュール依存の関連性をグラフUIで可視化し、AIの参照経路や知識の欠落を人間が監査できる仕組み。
399. **キャッシュ拡張生成（CAG）**: 比較的小規模で静的なナレッジベースを検索せず丸ごとモデルのコンテキストとKVキャッシュへ事前ロードして高速応答するアプローチ。
400. **コンテキストエンジニアリング**: 単発のプロンプト工夫を超え、検索・記憶・ツール出力・ドキュメント設計を統合してモデルへ最適な情報環境を提供する実践領域。

## 5. カスタムスキル・ルール設定・サンドボックス・実行環境（401〜500）

401. **AGENTS.md**: 複数ツール横断で標準化が進む、リポジトリ直下やディレクトリごとに配置するAIエージェント向けプロジェクト指示・規約ファイル。
402. **CLAUDE.md**: Claude Codeが起動時に自動読み込みし、ビルドコマンド・設計方針・コーディング規約・禁止事項を共有するための設定ドキュメント。
403. **GEMINI.md**: Gemini CLI等のエージェントがプロジェクト固有の文脈・開発手順・出力ルールを把握するために参照する指示ファイル。
404. **.cursorrules / .cursor/rules（MDC）**: CursorエディタでGlobパターンや説明文に応じて条件適用できる構造化ルール定義形式。プロジェクト標準を自動適用する。
405. **copilot-instructions.md**: GitHub Copilotのチャットやコード生成・PRレビューに対してリポジトリ固有の指針を与える公式カスタム指示ファイル。
406. **階層的ルール継承（Hierarchical Rules）**: グローバル設定→リポジトリルート→サブディレクトリ（例：`frontend/`、`infra/`）の順でルールを継承・上書きする設計。
407. **パス条件付きルール適用（Glob Scoping）**: `**/*.test.ts` や `migrations/**` のように編集対象ファイルパスに一致したときだけ関連ルールを注入し、トークン浪費を防ぐ仕組み。
408. **カスタムスキル（Agent Skills / SKILL.md）**: 特定の業務手順、ベストプラクティス、補助スクリプト、テンプレートを1フォルダにパッケージ化し、エージェントへオンデマンド付与する拡張単位。
409. **YAMLフロントマター（スキルメタデータ）**: `SKILL.md` 先頭に `name` や `description`（発動条件）を記述し、エージェントが適切なタイミングでスキルを発見・起動できるようにする定義。
410. **段階的開示（Progressive Disclosure）**: 常時はスキルの短い説明文だけを読み込み、タスクに該当した時のみ詳細な手順書やリファレンスを展開するコンテキスト節約アーキテクチャ。
411. **スキル同梱スクリプト（scripts/）**: スキルフォルダ内に決定論的なPython/Shellスクリプトを同梱し、AIの推測に頼らず確実なデータ処理・検証を実行させる構成。
412. **スキルリファレンス（references/）**: API仕様や長いチェックリストを本体 `SKILL.md` から分離配置し、必要箇所だけエージェントに読ませる保守性の高いドキュメント構造。
413. **スラッシュコマンド（Custom Slash Commands）**: `/review` や `/release` のように定型プロンプトやワークフローを短いコマンド入力で即座に呼び出せるUI/CLIショートカット。
414. **プラグインバンドル（Agent Plugins）**: 関連するスキル、カスタムエージェント、ルール、MCPサーバー、フックを1つの名前空間付きパッケージとして配布・有効化できる仕組み。
415. **マーケットプレイス・スキルレジストリ**: 組織内外で検証済みのプラグインやカスタムスキルを検索・インストール・バージョン管理できる流通基盤。
416. **サブエージェント定義（Custom Subagents）**: コード調査専任、セキュリティ監査専任、テスト生成専任など、固有のシステムプロンプトとツール権限を持つ専門エージェントを定義する仕組み。
417. **エージェントフック（Lifecycle Hooks）**: ツール実行前（PreToolUse）・実行後（PostToolUse）・セッション開始・完了などのイベントに連動して自動実行される拡張スクリプト。
418. **PreToolUseガードフック**: コマンド実行やファイル書き込みの直前に内容を検査し、危険なシェル操作や保護ファイル編集を自動ブロックする安全フック。
419. **PostToolUse自動整形フック**: エージェントがファイルを編集した直後にLinter・Formatter（Prettier、Ruff、gofmt等）を自動実行し、常に整形済みコードを維持する仕組み。
420. **カスタムモード（Custom Modes）**: Architect、Coder、Reviewer、Debuggerなどの役割ごとに利用可能ツール・編集可能パス・参照モデルを切り替えられるワークフロー機能。
421. **ペルソナ・ロール設計**: エージェントに期待する専門観点、判断基準、出力粒度、禁止事項を明確化して振る舞いのブレを抑えるプロンプト設計手法。
422. **出力テンプレート強制**: PR説明、障害報告書、設計書などのMarkdown構造をルールやスキルで固定し、チーム内で一貫した品質の成果物を得る運用。
423. **エージェント向けMakefile / Justfile**: ビルド、テスト、Lint、型チェックなどの頻出操作を統一タスク名に抽象化し、エージェントの誤コマンド実行と探索コストを減らす工夫。
424. **Pre-commitフック統合**: Gitコミット前にLint、型チェック、シークレット漏洩スキャン、テストを自動実行し、AI生成コードの品質ゲートとして機能させる仕組み。
425. **サンドボックス実行環境（Agent Sandbox）**: AIエージェントが実行する任意のシェルコマンドや生成コードをホストOSから隔離し、システム破壊や情報漏洩を防ぐ保護環境。
426. **OSネイティブサンドボックス（Seatbelt / Bubblewrap）**: macOSのsandbox-execやLinuxのBubblewrap・Landlock等を用い、軽量なオーバーヘッドでファイルシステムとネットワークを制限する技術。
427. **Dockerコンテナ隔離**: 開発環境とエージェント実行をコンテナ内へ閉じ込め、ホスト環境への影響遮断と環境再現性を両立する標準的な隔離方式。
428. **Dev Containers（devcontainer.json）**: IDE・ローカル・クラウドで同一の開発ツールチェーンと依存関係を自動構築するコンテナ定義仕様。AIエージェントの安定した実行土台となる。
429. **マイクロVM（Firecracker / Kata Containers）**: 仮想マシン並みの強固なカーネル隔離と数百ミリ秒の高速起動を両立し、信頼できないAI生成コードの安全なクラウド実行を支える技術。
430. **gVisor**: アプリケーションカーネルをユーザー空間で仲介し、コンテナからのシステムコールを厳格にフィルタリングするセキュアランタイム。
431. **E2B（Code Interpreter Sandbox）**: AIエージェント向けに設計されたクラウド型マイクロVMサンドボックス基盤。Python/Node/シェル実行やファイル操作をAPI経由で安全に隔離実行できる。
432. **Modal Sandbox**: コンテナイメージを秒単位で起動し、GPU利用や長時間エージェント実行をスケールアウトできるクラウドサンドボックス基盤。
433. **Daytona**: AIエージェント向けの高速・ステートフルな開発環境プロビジョニング基盤。ワークスペースの作成・スナップショット・破棄をプログラマブルに制御できる。
434. **Cloudflare Sandbox / Workers隔離**: V8 Isolateや軽量コンテナを活用してエッジ環境で安全にコード実行・プレビュー環境を提供するサーバーレス隔離基盤。
435. **WebContainers**: ブラウザタブ内のWebAssembly上でNode.jsランタイムと仮想ファイルシステムを動作させ、サーバー不要で安全な即時実行を実現する技術。
436. **Pyodide（Wasm Python実行）**: Pythonインタプリタと科学計算ライブラリをWebAssembly化してブラウザや軽量サンドボックス内で安全に実行できるランタイム。
437. **エフェメラル環境（使い捨て実行環境）**: タスクやPR単位でクリーンな環境を都度生成し、完了後に自動破棄することで状態汚染や残留シークレットを防ぐ運用原則。
438. **スナップショット・クローン環境**: 依存関係インストール済みのサンドボックス状態を保存し、複数エージェントへ瞬時に複製起動する高速化手法。
439. **ファイルシステムアクセス境界**: サンドボックス内でワークスペースディレクトリと `/tmp` のみ読み書きを許可し、ホームディレクトリやSSH鍵へのアクセスを遮断する制御。
440. **エグレス制御（ネットワーク遮断）**: サンドボックスからの外部通信をデフォルト禁止し、許可リスト（パッケージレジストリ等）のみ通信可能にしてデータ持ち出しを防ぐ仕組み。
441. **プロキシベースAPI仲介**: エージェント実行環境に本番APIキーを直接渡さず、外部プロキシ側で認証ヘッダを付与してシークレット漏洩を根本防止する設計。
442. **権限承認ポリシー（Allow / Ask / Deny）**: 読み取り系は自動許可、テスト実行はプレフィックス許可、破壊的操作や本番変更は毎回承認または禁止とする三段階ポリシー設計。
443. **コマンドプレフィックス許可リスト**: `git status` や `pytest` などの安全なコマンド体系を自動承認対象にしつつ、任意のパイプやコマンド置換を制限する運用。
444. **読み取り専用モード（Read-Only Execution）**: 調査・監査フェーズで書き込みツールや変更系SQLをシステムレベルで無効化し、意図しない改変を確実に防ぐ実行モード。
445. **データ損失防止ガード（DLP / Safety Gate）**: `DROP TABLE`、`rm -rf`、クラウド本番リソース削除など不可逆な破壊コマンドを検知し、明示的なユーザー確認を必須化する保護機構。
446. **シークレットスキャン（Gitleaks / TruffleHog）**: AIが生成・コミットしたコードやログにAPIキー、トークン、個人情報が混入していないかを自動検出・ブロックするツール。
447. **静的解析・SAST統合（Semgrep / CodeQL）**: AI生成コードに対してセキュリティ脆弱性やアンチパターンを自動スキャンし、結果をエージェントへフィードバックして修正させる連携。
448. **ソフトウェア構成解析（SCA / 依存関係監査）**: AIが追加した外部パッケージの既知脆弱性（CVE）、ライセンス、タイポスクワッティング（Slopsquatting）を自動検査する仕組み。
449. **Slopsquatting（スロップスクワッティング）**: LLMが幻覚で頻繁に出力する実在しないパッケージ名を攻撃者が悪意あるライブラリとして登録し、開発環境に紛れ込ませる攻撃手法。
450. **ガードレールエンジン（NeMo Guardrails / Guardrails AI）**: 入力・出力・ツール実行に対してポリシー違反、PII漏洩、トピック逸脱、有害出力をリアルタイム検査する中間フレームワーク。
451. **PIIマスキング・匿名化プロキシ**: 個人情報や社外秘識別子をLLM送信前にトークン化・マスクし、応答受信後にローカルで復元するプライバシー保護機構。
452. **監査ログ（Audit Trail）**: エージェントがどのプロンプトに基づき、どのツールを呼び出し、どのファイルやAPIを変更したかを改ざん困難な形式で記録するガバナンス機能。
453. **ワークスペース隔離（Git Worktree / Branch Mode）**: 並列稼働する各サブエージェントへ独立した作業ディレクトリを割り当て、ファイル編集の競合やビルド干渉を防ぐ仕組み。
454. **リソースクォータ制御（CPU / RAM / Timeout）**: 無限ループやメモリリークを起こしたAI生成コードがホストやクラウド基盤を枯渇させないよう、cgroup等で計算資源と実行時間に上限を設ける制御。
455. **バックグラウンドタスク・デーモン管理**: 開発サーバーやファイルウォッチャーなど常駐プロセスと、終了待ちコマンドを分離管理し、エージェントがハングしないようにする実行基盤。
456. **非同期通知・イベントループ**: 長時間ビルドやサブエージェント完了をポーリングせず、完了通知でエージェントを再起動する省トークン実行モデル。
457. **スケジューラ・Cron自動化（Agent Automations）**: 依存関係更新チェック、日次エラー要約、テスト監視などの定期タスクをスケジュール実行する自律エージェント運用。
458. **再現可能ビルド環境（Nix / mise / uv）**: 言語ランタイムやCLIバージョンを宣言的に固定し、AIエージェントと人間・CI間で「自分の環境では動く」差異をなくす環境管理ツール群。
459. **uv（高速Python環境管理）**: Rust製の超高速Pythonパッケージ・仮想環境マネージャ。依存解決とロックファイル運用が高速なため、AIエージェントの反復検証と抜群に相性が良い。
460. **ローカルエミュレータスイート**: Firebase Emulator Suite、LocalStack、Testcontainers等を用いて、本番クラウドへ接続せずローカル完結でAIに結合テストを実行させる基盤。
461. **Testcontainers**: テスト実行時にDockerで一時的なDB・Redis・Kafkaコンテナを自動起動・破棄し、AI生成コードの現実的な統合テストを高速検証するライブラリ。
462. **シードデータ・フィクスチャ管理**: 再現可能なテスト用ダミーデータを整備し、AIエージェントがUI確認やAPI検証を本番データなしで安全に繰り返せるようにする仕組み。
463. **モックサーバー・APIスタブ（MSW / WireMock）**: 外部決済やサードパーティAPIの挙動をローカルで再現し、エージェントが副作用なくエラー系や境界値をテストできるようにする環境。
464. **ビジュアルリグレッションテスト（Playwright / Storybook）**: AIによるUI変更前後のスクリーンショット差分を自動比較し、意図しないレイアウト崩れを検知する検証基盤。
465. **アクセシビリティ自動監査（axe-core）**: AIが生成したHTML・コンポーネントに対し、WAI-ARIA、キーボード操作、コントラスト比の違反を自動検出して修正へつなげるツール。
466. **型チェッカー高速フィードバック（TypeScript / mypy / Pyright）**: 静的型検査をエージェントの編集ループに組み込み、インターフェース不整合やnull安全違反を即座に自己修正させる実践。
467. **超高速Linter/Formatter（Biome / Ruff / Oxlint）**: Rust製ツールによりミリ秒単位でコード検査・整形を完了させ、エージェントの反復サイクルを高速化する開発エコシステム。
468. **ミューテーションテスト（Stryker / mutmut）**: AIが生成したテストコードが形式的なカバレッジ稼ぎに終わっていないか、コードへ意図的にバグを注入して検出力を検証する手法。
469. **プロパティベーステスト（Hypothesis / fast-check）**: 大量のランダム境界入力を自動生成して不変条件を検証し、AIが見落としやすいエッジケースのバグを炙り出すテスト手法。
470. **契約テスト（Contract Testing / Pact）**: マイクロサービスやフロントエンド・バックエンド間のAPI仕様合意を機械検証し、AIによる片側変更での破壊を防止するテスト技法。
471. **仕様駆動開発（Spec-Driven Development）**: コード生成前に要件・API契約・受け入れ基準を構造化仕様書として確定し、仕様を単一情報源としてAI実装と検証を回す開発手法。
472. **ハーネスエンジニアリング（Harness Engineering）**: AIエージェントが安定して高品質な成果を出せるよう、テスト・Lint・サンドボックス・フィードバックループ・観測基盤を体系設計する領域。
473. **エージェント評価ハーネス（Eval Harness）**: 複数の実務課題リポジトリを隔離コンテナで並列実行し、ルール変更やモデル更新の成功率・コスト・所要時間を定量比較する検証基盤。
474. **コンテキストファイルのリント・監査**: `AGENTS.md` やカスタムスキルが肥大化・矛盾・陳腐化していないかを定期チェックし、ルール品質を維持するガバナンス運用。
475. **ルール肥大化・指示衝突対策**: 過剰なルール記述によりモデルが重要制約を見落とす問題を防ぐため、簡潔性・優先度明示・動的ロードを徹底する設計原則。
476. **ワークフローのスキル化（Workflow Distillation）**: 対話を通じて確立した複雑な問題解決手順やデバッグノウハウを、再利用可能な `SKILL.md` として抽出・資産化するプロセス。
477. **チーム横断ルール配布（Shared Config Repo）**: 組織共通のコーディング規約、セキュリティルール、スキル群を中央Gitリポジトリやパッケージで管理し、全プロジェクトへ同期配布する仕組み。
478. **エンタープライズSSO・RBAC管理**: AI開発ツールの利用権限、許可モデル、接続可能MCPサーバーをIdP連携とロールベースで統制する企業向け管理基盤。
479. **モデル利用ポリシー・許可リスト**: 機密区分に応じて利用可能なLLMプロバイダ・リージョン・学習オプトアウト設定を組織レベルで強制するコンプライアンス制御。
480. **シャドーAI対策**: 承認されていない個人アカウントや外部AIサービスへのコード貼付を防ぎ、安全で使いやすい公式AI開発環境を整備するセキュリティガバナンス。
481. **コード生成テレメトリ・生産性計測**: AI補完の採用率、PRリードタイム、レビュー手戻り率、バグ発生率を追跡し、ツール投資対効果と品質影響を客観評価する仕組み。
482. **PRレビュー自動化ゲート**: AI生成コードを含むすべてのPRに対し、自動テスト・セキュリティスキャン・AI一次レビュー・人間最終承認を組み合わせる品質保証体制。
483. **AI生成コードの所有権・説明責任**: AIが書いたコードであってもマージ承認した開発者・チームが保守責任と設計理解を持つというエンジニアリング組織の原則。
484. **コミット粒度・トレーサビリティ規約**: エージェントの作業単位ごとに意味のあるコミットメッセージ（Conventional Commits等）で履歴を残し、後から原因追跡・リバートしやすくする運用。
485. **作業ログ・プロンプト履歴管理**: セッションごとの指示内容、判断理由、変更結果を軽量ドキュメントへ記録し、別セッションや別メンバーへの引き継ぎコストを下げる工夫。
486. **チェックリスト駆動検証（Verification Before Completion）**: 完了報告を行う前に必ずビルド・テスト・差分確認のコマンド実行結果を一次証拠として確認するエージェント行動規範。
487. **ドライラン（Dry-Run）実行**: インフラ変更（Terraform plan等）やマイグレーション、一括ファイル操作を実適用前にシミュレーション実行し、影響範囲を事前確認する安全手順。
488. **フィーチャーフラグ統合（LaunchDarkly / OpenFeature）**: AIが実装した新機能をフラグ制御下で段階公開し、問題発生時にデプロイ巻き戻しなしで即座に無効化できるリリース設計。
489. **カナリアリリース・自動ロールバック**: 新コードの公開後にエラー率やレイテンシ異常を観測基盤が検知した場合、自動で前バージョンへ切り戻す安全なデリバリー基盤。
490. **プレビュー環境自動生成（PR Preview）**: Pull Requestごとに一時的な動作確認URLとDBブランチ（Neon / Supabase Branching等）を自動生成し、AIと人間が実動作を検証できる仕組み。
491. **データベースブランチング（Neon / PlanetScale）**: Gitブランチのようにコピーオンライトで瞬時にDBの複製環境を作成し、AIエージェントが安全にスキーマ変更を検証できる基盤。
492. **インフラストラクチャ・アズ・コード検証（Terraform / Pulumi）**: AIが生成したクラウドリソース定義に対し、構文検証・ポリシー検査（OPA/Checkov）・コスト見積もりを自動実行するパイプライン。
493. **Policy as Code（Open Policy Agent / OPA）**: セキュリティ・コンプライアンス・デプロイ規則をRego等のコードで定義し、エージェントの出力や実行計画を機械的に合否判定する仕組み。
494. **ローカル開発証明書・閉域プロキシ対応**: 企業ネットワークのTLSインスペクションや社内プロキシ環境下で、CLIエージェントやMCPサーバーが安全に動作するための証明書・通信設定。
495. **オフライン・エアギャップAI開発環境**: インターネットから完全遮断された環境内で、オンプレミスLLM推論サーバー・ローカルパッケージミラー・社内RAGを統合運用する構成。
496. **IDEワークスペース信頼設定（Workspace Trust）**: 信頼されていない外部リポジトリを開いた際に、悪意あるルールファイル・フック・MCP設定・タスクの自動実行を抑止するセキュリティ機能。
497. **サプライチェーン署名検証（Sigstore / Cosign）**: 導入するMCPサーバー、コンテナイメージ、プラグインパッケージの署名と出所（Provenance）を検証し改ざんを防ぐ仕組み。
498. **エージェント障害復旧・タイムアウト設計**: 外部API停止やエージェントの無限ループ時に、ステップ上限・予算上限・タイムアウトで安全停止して状態を保存するフェイルセーフ設計。
499. **人間とAIの協働プロトコル（Approval UX）**: 計画提示、差分確認、質問フォーム、進捗チェックリストを通じて、人間が最小労力で的確に方向修正できるインタラクション設計。
500. **AI駆動開発エコシステム統合**: IDE、CLIエージェント、MCP、推論基盤、RAG、カスタムスキル、隔離サンドボックスを疎結合に組み合わせ、継続的に進化させられる開発プラットフォーム全体像。
